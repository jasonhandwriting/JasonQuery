# JasonQuery.IntegrationTests

`JasonQuery.IntegrationTests` validates JasonQuery against real Oracle, PostgreSQL, SQL Server, and MySQL databases. It covers provider connectivity, paged reads, schema metadata, special data types, value formatting, transaction semantics, DDL behavior, and locking.

The exact test count is intentionally not maintained here. Visual Studio Test Explorer and the latest test results are the source of truth.

## Safety

- All database families are disabled by default in the committed template.
- Use dedicated test databases and accounts. Never run this suite against production or irreplaceable data.
- Tests create, query, update, commit, roll back, lock, and drop database objects.
- Test-owned objects use the reserved `JQ_IT_` prefix.
- Integration tests are non-parallel because JasonQuery currently uses shared connection state and because locking tests require controlled sessions.
- Cleanup is performed by the test fixtures, but an interrupted process may leave `JQ_IT_` objects that should be reviewed before the next run.
- The real runsettings file may contain passwords and is ignored by Git. Only the `.runsettings.example` template may be committed.

## Prerequisites

- Visual Studio 2022.
- .NET Framework 4.8 Developer Pack.
- An x64 test process.
- A successfully configured JasonQuery build environment, including required local provider dependencies.
- One or more dedicated Oracle, PostgreSQL, SQL Server, or MySQL test environments.
- Test accounts with the permissions required to create, query, update, lock, and drop `JQ_IT_` objects.

## Configure with a Local Runsettings File

1. Copy `JasonQuery.IntegrationTests.runsettings.example`.
2. Name the local copy `JasonQuery.IntegrationTests.runsettings`.
3. Enter local test-database values in the copy.
4. Set `Enabled=true` only for the database families you intend to test.
5. In Visual Studio 2022, select **Test > Configure Run Settings > Select Solution Wide Runsettings File** and choose the local file.
6. Confirm that `JasonQuery.IntegrationTests.runsettings` remains ignored before staging or committing changes.

If a database family is disabled or a required setting is missing, its tests call `Assert.Inconclusive` and appear as Inconclusive/Skipped instead of Failed.

## Environment Variable Overrides

Integration settings can also be supplied through environment variables. Environment variables take precedence over values from the selected runsettings file.

The variable name is generated by converting the runsettings parameter to uppercase, replacing periods with underscores, and adding the `JQ_IT_` prefix. Examples:

```text
Oracle.Enabled                 -> JQ_IT_ORACLE_ENABLED
Oracle.Password                -> JQ_IT_ORACLE_PASSWORD
PostgreSql.ConnectionString    -> JQ_IT_POSTGRESQL_CONNECTIONSTRING
SqlServer.ConnectionString     -> JQ_IT_SQLSERVER_CONNECTIONSTRING
MySql.Enabled                  -> JQ_IT_MYSQL_ENABLED
```

Do not place real credentials in committed scripts, documentation, or example files.

## Run the Tests

1. Build the solution for `x64`.
2. Open Visual Studio Test Explorer.
3. Confirm that the intended local runsettings file is selected.
4. Run the complete `JasonQuery.IntegrationTests` project, or filter by database or functional category.
5. Review Failed, Skipped, and Inconclusive results separately. An unconfigured database is expected during ordinary development, but it does not satisfy a formal release verification.

## Categories

Every real-database test uses the `Integration` category and a database category:

- `Oracle`
- `PostgreSql`
- `SqlServer`
- `MySql`

Additional functional categories include:

- `Paging`
- `Schema`
- `KeyInfo`
- `SpecialTypes`
- `ProviderSchema`
- `ProviderValue`
- `Formatter`
- `Transaction`
- `DDL`
- `Locking`

## Coverage Areas

- Connection and scalar-query smoke tests.
- Paged query execution and requested-row behavior.
- Schema-table metadata and primary-key detection.
- Provider-specific and special data types.
- JasonQuery value-arrangement and formatting behavior.
- DML visibility across commit and rollback boundaries.
- Database-specific DDL transaction semantics.
- Defensive repeated Commit and Rollback handling.
- Two-session locking conflicts and lock release.

## Adding Integration Tests

- Reuse the existing infrastructure, fixtures, and SQL dialect helpers.
- Mark each test with `Integration`, the database category, and an appropriate functional category.
- Keep the test non-parallel and deterministic.
- Use only reserved `JQ_IT_` object names.
- Create and clean up test data within the fixture lifecycle, including failure paths.
- Avoid assumptions about unrelated schemas, tables, or user data.
- Add new configuration keys to `.runsettings.example` with disabled or non-secret placeholder values.
- Never add the local `JasonQuery.IntegrationTests.runsettings` file to Git.
